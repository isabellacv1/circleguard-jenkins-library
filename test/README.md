# Tests of the library

Behavioural tests for the reusable steps. They are **unit tests**: every Jenkins
step (`sh`, `echo`, `error`, `env`, `currentBuild`, `file`, `fileExists`,
`readFile`, `writeFile`, `archiveArtifacts`, `junit`, `input`, `withEnv`,
`withCredentials`, `usernamePassword`, `timeout`) is replaced by an in-memory
stub, so the tests need

- **no Docker image** (nothing is downloaded),
- **no network**,
- **no AWS credentials** and no Terraform/Trivy binary installed.

The sibling steps called by a step (`runInContainer`, `terraformValidate`,
`ensureBuildx`, `dockerCleanup`, `trivyImageScan`, `deployKubernetes`,
`verifyIngress`, `smokeTests`) are stubbed too; the ones used
to assert an execution order are also recorded in `trace` (in the same sequence
as the `sh` commands) and everything written with `writeFile` is recorded in
`written` (file → content). Every call to `input` is recorded in `inputs`
(`opts.inputResult` returns its value, `opts.failInput` throws for an expired or
cancelled approval). `opts.failShContains`, `opts.failShContainsList` and
`opts.failWriteFileContains` make **one** command or **one** file fail, so the
failure paths of a single step can be tested without breaking the others.
The `realSh*` options execute the selected shell fragment with the local
`bash` in an isolated temporary directory, so secrets, `curl` retries and
cleanup traps are verified as real shell behaviour, not only as source text.

**Scope:** these are unit tests over mocked Jenkins steps. They prove the logic
of the steps (commands built, gates, provenance checks, messages and evidence);
they are **not** a validation of Jenkins, Docker, Terraform or AWS — those real
validations are listed in the main README (*Known limitations and follow-ups*)
and are still pending. The suite currently runs **177 tests**.

## Why `test/` and not `src/`

Jenkins loads `src/` and `vars/` when the library is used by a build. These
files must never reach the runtime of a pipeline, so they live outside both
directories and are only executed by hand (or by a future CI job of this
repository).

## Running them

They only need a Groovy runtime (any Groovy 3/4/5 works; Groovy is already in
the Gradle caches of the developer machines, so nothing has to be installed):

```bash
# from the root of the library
java -cp "$(find ~/.gradle -name 'groovy-3.0.25.jar' | head -1)" \
     groovy.ui.GroovyMain test/StepTests.groovy

# or passing the root of the library explicitly
java -cp <groovy.jar> groovy.ui.GroovyMain test/StepTests.groovy /path/to/circleguard-jenkins-library
```

Exit code `0` means all tests passed; `1` reports the failing ones.

## What is covered

|------|--------|
| `runInContainer` | mount limited to the job with `volume-subpath` (no whole volume, no host path), **`--mount` tokenised separately from its value** (regression for `unknown flag: --mount type`), `--user`/`HOME`, env vars passed **by name only**, rejection of a workspace outside `/var/jenkins_home/workspace` and of a workspace that does not exist yet, rejection of `:latest` and untagged images, missing workspace/command, `returnStatus` |
| `terraformValidate` | free-space check **first** (`df -Pk`) and abort with the available/threshold message before any Terraform command, creation of the plugin cache, `TF_PLUGIN_CACHE_DIR` passed by name and scoped with `withEnv`, `fmt -check` + `init -backend=false` + `validate` per root, **never** `plan`/`apply`/`destroy`/`-upgrade`, no AWS credentials, fail-fast on a missing root |
| `trivyScan` | `trivy config`, `--severity HIGH,CRITICAL`, `--exit-code 1`, cache in the workspace (`/ws/.trivy-cache`) and never shared, exclusions of `.terraform`/`.trivy-cache`/`*.tfstate*`/`*.tfplan*`, report per build (`trivy-iac-report-<build>.txt`) echoed and archived, **previous build report never archived**, correct message when no report was generated, blocking on findings with the evidence kept, `--ignorefile` only when the file exists, one target per invocation |
| `terraformPlan` | `init -backend=true` (**never** `-backend=false`, `-reconfigure` or `-migrate-state`) + `plan -no-color -input=false -lock=true -detailed-exitcode -out=ci-<env>-b<build>.tfplan` + sidecar `<plan>.info` (build, commit, root, changes, status, sha256, date; `sha256sum` **fail closed**) and **returns `sha256`**, **credential bound exactly once** with id `aws-terraform-credentials` and variables `AWS_ACCESS_KEY_ID`/`AWS_SECRET_ACCESS_KEY`, env vars passed **by name only** (no value, no interpolation), `AWS_DEFAULT_REGION`/`TF_IN_AUTOMATION`/`TF_INPUT`/`TF_PLUGIN_CACHE_DIR` via `withEnv`, exit codes **0 / 2 / 1** interpreted (`changes` flag, failure message with the AccessDenied rule), plan **never archived**, stale plan removed first, free-space gate **before** the credential is bound (parser reused from `terraformValidate`), fail-fast on a missing root / missing `versions.tf` / unsafe root path / plan name without `.tfplan` / empty credential id, plan **never applied by this step** |
| `terraformApply` | **provenance before anything**: `TF_PLAN_BUILD == BUILD_NUMBER`, `TF_PLAN_ROOT`/`TF_PLAN_FILE`/`TF_PLAN_INFO` match, `TF_PLAN_CHANGES` valid and equal to the sidecar, `GIT_COMMIT` equals the sidecar, `status` coherent with `changes` (`2` ⇔ `true`), `sha256` recomputed with `sha256sum` and compared with the sidecar (**fail closed** if the tool is missing or the hash differs), plan + sidecar exist, `.applied` marker absent → each failure runs with **`sh` empty**; `SKIPPED_NO_CHANGES` registers the outcome and omits `init`/`apply` (no credential, no lock); with changes: `df` → `sha256sum` → `mkdir` → `init -backend=true` → **`apply -lock=true <plan>`** (never `-lock=false`, `-auto-approve`, `-destroy`, `-replace`, no `terraform output`), credential bound once by name, order **marker → evidence → cleanup**, evidence with `Outcome: APPLIED`/`SKIPPED_NO_CHANGES` archived (no credential, no output), original failure **rethrown unchanged** with the AccessDenied guidance **only for an AccessDenied** (`failShMessage`), and explicit, non-retried messages that say the infrastructure may have changed: `INFRASTRUCTURE MAY HAVE CHANGED` + `could NOT be written` vs `WAS written … could NOT be archived` vs the cleanup (`failWriteFileContains` / `failArchiveContains` / `failShContains`, no `retry(`) |
| `terraformApproval` | **no container, no Terraform, no AWS**: the only command is a local `sha256sum`. Before `input` it validates `TF_PLAN_BUILD == BUILD_NUMBER`, `TF_PLAN_ROOT`/`TF_PLAN_FILE`/`TF_PLAN_INFO`, `TF_PLAN_CHANGES == 'true'`, `TF_PLAN_SHA256` and `GIT_COMMIT`, the sidecar (build, commit, root, changes, 64-hex `sha256`), sidecar `sha256` == `TF_PLAN_SHA256`, recomputed sha == sidecar (**fail closed**), `createdAt` valid, not in the future and ≤ `maxAgeMinutes` → every failure runs with **`sh` empty (or only `sha256sum`), `input` never called and no `TF_APPROVED_*` persisted**; the `input` carries `submitter`, `submitterParameter: 'approvedBy'`, `timeout`, `timeUnit: 'MINUTES'` and a message with build/commit/root/sha/changes/age; on success it persists `TF_APPROVED_BY/AT/PLAN_SHA/BUILD` and returns them; `FlowInterruptedException` (timeout or cancel) echoes `NO infrastructure was changed` and **rethrows the original** (`e.is(...)`); an approval without a valid identity is rejected without persisting anything |
| `runE2E` | mount limited to the job with **`volume-subpath`** (never `-v <volume>:` and never a host path), `--mount` tokenised separately from its value, `-w /jh/tests/e2e-playwright`, `--user`/`HOME`, credentials bound once with `E2E_USERNAME`/`E2E_PASSWORD` **by name**, Playwright command and pinned image kept, **`results.xml`, `playwright-report/` and `test-results/` are cleaned before Playwright through a real shell**, **a failed cleanup stops the step before Playwright, JUnit and archiving**, **missing or empty `results.xml` fails before publication**, **the original container failure is rethrown even when report publication also fails**, URLs shell-quoted (including embedded quotes), rejection of a workspace outside `/var/jenkins_home/workspace` and of a workspace that does not exist yet (nothing runs), no step mounts the whole volume anymore |
